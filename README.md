# 通用控台小卡 General_KT

按《通用控台小卡.pdf》适配 APM32F103C8T6，沿用参考工程的 STM32F1 HAL 驱动与 Keil/EIDE 构建方式。参考版本为 PANTAO_WIFI/PanTao_Ctrl 与 DANJIE_WIFI/Danjie_Ctrl。

## 硬件连接

| 功能 | 引脚/接口 |
| --- | --- |
| 状态指示灯（低电平点亮，每 500ms 翻转） | PA1（芯片第 11 脚） |
| 主板通信 | USART2：PA2 TX、PA3 RX，115200、8N1 |
| 旋钮 | TIM1：PA8 CW、PA9 CCW |
| 摇杆上、下、左、右 | PA5、PA4、PA7、PA6，低电平有效 |
| 拍拍按键 1～6 | PA10、PA11、PA12、PB5、PB6、PB7，低电平有效 |
| 扩展按键 1、2 | PB8、PB9，低电平有效 |
| 数码管 J4 | PB15 SER、PB14 OE、PB13 SRCLK、PB12 RCLK |
| 调试接口 | PA13 SWDIO、PA14 SWCLK |

原理图没有旋钮按压开关和 RGB 灯。六路拍拍按键沿用 `Code2=0x01`、编号 1～6；两路扩展按键沿用原键盘 `Code2=0x02`、编号 1～2；旋钮沿用 `Code2=0x03`，正向计数事件为 `ExpandCode=0x00`，反向为 `0x01`。短按在释放时判定，拍拍按键长按门限为 800ms，长按重复频率为 3Hz，沿用原按键处理方式。

主板下发只保留 `Code1=0x02, Code2=0x01` 数码管数据。原有灯带亮度 `0x02`、灯光场景 `0x03`、控台亮度 `0x04`、控台按键灯 `0x05` 均忽略；RGB 任务、PWM、TIM3 与相关 DMA 已移除。PA1 状态指示灯保留，沿用每 500ms 翻转的闪烁方式。

## 摇杆协议

沿用原 14 字节协议，`Code1=0x03`、新增 `Code2=0x04`：

| 字节（从 0 开始） | 内容 |
| --- | --- |
| 0 | `0xAA` 帧头 |
| 1 | `0x00` 重发次数 |
| 2 | 消息 ID，每帧递增，255 后回到 0 |
| 3、4 | `0x03 0x04` |
| 5、6、7 | `0x00 0x00 0x00` |
| 8 | 方向：1 上、2 下、3 左、4 右、5 左上、6 左下、7 右上、8 右下 |
| 9 | `0x00` ACK 字节 |
| 10 | `0x01` 短按、`0x02` 长按、`0x03` 松开 |
| 11、12 | 前 11 字节的 CRC16，高字节在前、低字节在后 |
| 13 | `0x55` 帧尾 |

CRC 算法沿用参考工程：初始值 `0xFFFF`，反向多项式 `0xA001`，无最终异或。示例（ID=1，上方向短按）：

```text
AA 00 01 03 04 00 00 00 01 00 01 7B BD 55
```

方向整体稳定 15ms 后确认；相近时刻闭合的两路触点合成一个斜向方向，不分别发送上、左等两条消息。上下同时有效、左右同时有效或三路以上同时有效按回中处理。

短按沿用参考控台的释放判定方式：不足 800ms 的方向在松开时先发短按、再发松开；达到 800ms 后上报长按，持续保持时每 333ms 重复一次，松开只发松开。回中不发送方向 `0x00`，松开报文携带被释放的方向。转向先结束旧方向，再对新方向独立计时。例如上转左上再回中，短按时依次发送 `上/短按、上/松开、左上/短按、左上/松开`。

本次仅修改控台仓库；两个参考主板当前只有 `Code2=0x01/0x02/0x03` 接收分支，新摇杆协议需要主板增加 `0x04` 接收/转发分支后联调。

## 编译验证

Windows 可使用 `MDK-ARM/General_KT.uvprojx`，或 EIDE 工程。Linux 安装 GNU Arm Embedded 工具链后执行：

```sh
python3 verification/build_firmware.py --toolchain /path/to/arm-gcc/bin
```

脚本读取 Keil 项目中的实际 C 源文件、宏和包含路径，用 Cortex-M3 配置完整编译并链接到 64KB Flash、20KB SRAM，输出 `build/firmware/General_KT.elf/.hex/.bin`。构建产物不进入 Git。GNU Arm 编译用于验证，尚需在实板上验证 APM32 的串口、编码器物理方向和数码管段码。

## 自动化测试

主机上安装 GCC 后运行：

```sh
python3 verification/run_tests.py
```

测试直接编译实际 `KeyTask`、摇杆扫描、普通按键扫描、通信组帧、UART 回调、环形缓冲区和 CRC 源码，仅模拟 GPIO/UART 硬件边界，开启 AddressSanitizer/UndefinedBehaviorSanitizer。覆盖八方向、方向切换、斜向组合、抖动、800ms 门限、长按重复、短按/长按释放、非法组合、扫描延迟、时钟回绕、全部八路实体按键、14 字节帧与 CRC、消息 ID 回绕、四类灯光指令忽略、数码管下发、分段/粘连帧和坏帧恢复。
